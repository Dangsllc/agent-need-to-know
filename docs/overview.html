Open source · Plugin for Claude Code

Give each project only the plugins it needs.

Every plugin and connector you turn on loads into every Claude Code session, in every folder. devconsole switches them on per project, the way AWS IAM grants permissions: projects are users, profiles are groups, and nothing is on unless a profile grants it.

How it works

How a session gets its plugins and connectors

1

Write small profiles

A profile is a named bundle for one kind of work. Keep each one small so they combine.

baseline→ what every project gets
2

Attach profiles to each project

A project gets everything its profiles grant, and nothing else.

devconsole writes that project's switches

Which plugins are on and which connectors are off, in Claude Code's own settings. It backs them up first.

A session loads only that list

Open Claude Code in api-service and it gets engineering, Python intelligence and the baseline connector. Nothing from your other projects comes along.

Where plugins come from

Installed once, shared by every project

Plugin files download one time into a shared cache. Turning a plugin on for a project adds one line to that project's settings. Nothing is copied into the project.

Walkthrough

Running it

1 · Install and point it at your projects

Add the plugin, then run setup once. It asks where your projects live and copies in starter profiles.

# in Claude Code
/plugin marketplace add <owner>/devconsole
/plugin install devconsole@devconsole
/project-setup init
? Where do your projects live?  ~/code
✔ 6 projects found, 6 new

2 · Set up a project

Open a session in a project. The hook sees it has no profile and offers an interview: it reads the stack, asks one round of questions and proposes profiles.

devconsole: api-service has no profile. Offer /project-setup.
found     pyproject.toml, FastAPI, Dockerfile
? What will you mostly do here?  Build and fix code
? Does it touch sensitive data?  Yes
proposal  code-core · lang-python · secure-code
✔ Applied. Takes effect in your next session.

3 · See every project on one page

Type devconsole in a terminal. Each project shows its profiles and status. Attach or detach a profile with a click. Every change previews the projects it touches before it applies.

devconsoleProjectsProfilesCapabilities
ProjectStatusProfiles
api-serviceokcode-corelang-pythonsecure-code
marketing-siteokweb-designmarketing
scratchnewno profile yet

4 · Keep it current

New plugins and connectors land in an inbox. Add one to a few profiles, or to baseline to turn it on everywhere. Retire an old one from every profile at once.

$ devconsole inbox
new      Linear (connector)
$ devconsole capability adopt Linear --profiles planning --dry-run
affects  roadmap, api-service
$ devconsole capability adopt Linear --profiles planning
✔ 2 projects updated

A workspace is a small folder that gives one session access to several projects, with its own profiles. Use one when the work crosses projects, because a session only loads what its starting folder allows.

The rules

Three rules, borrowed from IAM

Allow is a union

A project gets everything its attached profiles grant, plus the default profile every project gets.

Connectors start off

A connector is on only where a profile grants it. One your account adds later starts off everywhere.

A deny wins

A profile can deny a plugin or connector, and that beats any grant. One-off exceptions are possible, and the page flags them.

Try it

Two commands to start

/plugin marketplace add <owner>/devconsole
