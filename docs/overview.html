Open-source plugin for Claude Code

devconsole: least-privilege plugins and connectors for every project

Every plugin and connector you turn on adds to the context of every Claude Code session, in every folder. devconsole gives each project only what its work needs, using the model you already know from AWS IAM: projects are users, profiles are groups, and nothing is on unless a profile grants it.

How a session gets its plugins and connectors

What you edit Tools that act Files written per project Plugin sources Not used by Claude Code

Install once, switch per project

A plugin's files live in one shared cache. Turning it on for a project adds one line to that project's settings.local.json. Nothing is copied into the project folder.

Login matters only for synced plugins

Marketplace plugins install on any account. Plugins synced from claude.ai load only while you're logged into the account that has them, so prefer the marketplace version when both exist.

Changes land at the next session

Plugins and connectors load when a session starts, based on the folder it starts in. For work that crosses projects, start in a workspace folder that has its own profiles and access to the other folders.

The rules

Allow is a union

A project gets the plugins and connectors of every profile attached to it, plus the default profiles every project gets.

Connectors are denied by default

A connector is on only where a profile grants it. A connector your account adds later starts off everywhere.

An explicit deny wins

A profile can deny a plugin or connector, and that beats any grant. One-off per-project exceptions exist, but the page flags them so they don't pile up.

What you get

One page for every project

A local page lists each project, its profiles and its status (ok, drift, missing, new), with switches. Every change previews the projects it affects before it applies.

New folders don't slip through

A session-start hook notices a folder with no profile and offers /project-setup, an interview that looks at the stack and proposes a set of profiles.

A lifecycle for capabilities

New plugins and connectors land in an inbox. Add one to a few profiles, or to the default profile to turn it on everywhere. Retire an old one from every profile at once.

Workspaces for cross-project work

A small folder that grants a session access to several projects, with its own profiles. In IAM terms, a role you take on for one kind of work.

Careful with your settings

Changes go through Claude Code's own plugin commands. Settings are backed up before each write, every change is logged, and nothing is deleted. The page listens on localhost only and needs a per-run token.

Small and dependency-free

Python standard library and one HTML file. The plugin itself adds a couple of hundred tokens to a session; the profiles it manages decide the rest.

Try it

/plugin marketplace add <owner>/devconsole
/plugin install devconsole@devconsole
/project-setup init      # pick your projects folder, then set up each project
devconsole               # open the page (or /devconsole in a session)

Profiles live in two small JSON files you own. The plugin ships with starter profiles and sends nothing anywhere.
